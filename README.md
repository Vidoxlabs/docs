# Docs

Documentation hub for the Vidoxlabs agent family. Pages are written here, and every public repository's documentation lands here verbatim through a scheduled sync: one source of truth upstream, one place to read and render it all.

**Status: `0.1.0`, hub pages, sync engine, and CI runs.** Selection, planning, provenance, and rendering live in `src/sync-core.mjs`, and `npm test` covers them. The site handoff in [docs/site-integration.md](docs/site-integration.md) is `specified`, not shipped.

## What lives here

- `docs/`: pages owned by this repository. `docs/sources-index.md` is generated by the sync; every other page is written by hand.
- `sources/`: verbatim copies of each source repository's documentation. Never edited here; a correction travels upstream, and the next sync brings the copy back.
- `manifest.json`: the machine map of every copy: repository head, per-file SHA-256, sizes, and the run timestamp.

## How the sync works

The hub pulls; no source repository carries any integration, webhook, or credential. [docs/sync.md](docs/sync.md) holds the full contract. The short version:

1. Ask GitHub for each source's `main` head.
2. Skip any source whose recorded head and on-disk digests already match.
3. For each moved source, fetch its tarball and copy the selected text files into `sources/<name>/`.
4. Write `manifest.json`, regenerate `docs/sources-index.md`, and commit the run.

Pull requests land as sources when they merge: the sync watches `main` only, so a merged documentation change appears on the next run, inside the schedule's window. Need a run sooner: dispatch the workflow by hand.
